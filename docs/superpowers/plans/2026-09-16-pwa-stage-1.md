# PWA Stage 1 — "The Supermarket Case" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An installable app that opens with no signal, logs an expense, queues it, and syncs it to the sheet when the phone has a connection — plus the account list and balances it needs to do that.

**Architecture:** The Apps Script project gains a JSON API (`Api.gs`, `doPost`) gated by a verified Google ID token, and an `Id` column that makes a replayed entry a no-op instead of a duplicate money row. The client is plain ES modules on GitHub Pages: a service worker caches the shell, IndexedDB holds the last synced views and a write queue, and every money rule stays on the server.

**Tech Stack:** Apps Script (ES5 style) on the server; browser-native ES modules, IndexedDB and a hand-written service worker on the client; `node` as a bare assertion runner. No bundler, no framework, no npm dependencies.

**Spec:** `docs/superpowers/specs/2026-09-16-pwa-client-design.md` — read it before starting any task. Stage 1 is §9.1; later stages get their own plans.

## Global Constraints

- **Server code is ES5** (`var`, `function`, no arrows/`const`/`let`/template literals) and matches the sibling repo's style. **Client code is modern ES modules** (`const`/`let`, arrow functions, `async`/`await`) — it only ever runs in a current mobile browser.
- **Comprehension-first.** Non-obvious choices get a comment saying *why*. Commit messages explain reasoning.
- **No agent touches the live spreadsheet, the Apps Script project online, Google Cloud, or GitHub.** No `clasp push`, no `clasp deploy`, no `gh`, no `git push`. Those are Vin's, as runbook steps.
- **No money rule is implemented on the client.** The only client arithmetic permitted in this stage is summing queued amounts for a pending badge (spec §7.3).
- **No secret in tracked source.** The OAuth client id and the API URL live in `config.js`, which IS committed (it is public by design on Pages — see Task 3). The script id, sheet id, allow-list and `PAYERS` stay in the Apps Script project.
- **Every server write keeps its re-read and write inside one `LockService.getScriptLock()`.**
- **`fail_()` takes string literals only.**
- **Verification:** the sibling repo's `./check.sh` (from `home-economy-app/`) must stay green — `ledger self-check passed`, `bills self-check passed`, `self-check passed`, `bills render smoke passed`; its mid-run `TypeError: x.y is not a function` trace is EXPECTED. This repo gets its own `./check.sh` in Task 3; from then on it must stay green too.
- **Never write a raw NUL byte into a file.**

```js
/**
 * Has this entry already been written? The id is generated on the phone
 * before a queued entry is sent, so a retry after a dropped reply finds its
 * own id here and writes nothing — without it, one lost response is one
 * duplicated money row (PWA spec §4.2).
 *
 * A blank id never matches: rows written before the column existed all share
 * it, and they are not duplicates of each other.
 */
function idExists_(entries, id) {
  var key = String(id == null ? '' : id).trim().toLowerCase();
  if (!key) return false;
  return entries.filter(function (e) {
    return String(e.id || '').trim().toLowerCase() === key;
  }).length > 0;
}
```

```js
/**
 * JSON API for the PWA client (../../home-economy-pwa-client).
 * Design: that project's docs/superpowers/specs/2026-09-16-pwa-client-design.md.
 *
 * This file adds an entry point; it does not change one. doGet and the
 * google.script.run handlers in Code.gs are untouched, and the Apps Script
 * web app keeps working exactly as before — the two run side by side from one
 * deployment each (spec §3.3).
 *
 * Everything here is transport: parse, authenticate, dispatch, shape a reply.
 * Every rule about money lives in Ledger.gs and Bills.gs and is reached
 * through the same handlers the Apps Script UI calls.
 */

/** The op names the client may ask for, mapped to the handlers they reach. */
function opHandler_(op) {
  var ops = {
    bootstrap: function (a) { return getBootstrap(); },
    ledger: function (a) { return getLedger(a.ledger); },
    entries: function (a) { return getEntries(a.ledger, a.account, a.offset); },
    addEntry: function (a) { return addEntry(a.entry); },
    updateEntry: function (a) { return updateEntry(a.ledger, a.row, a.fp, a.entry); },
    voidEntry: function (a) { return voidEntry(a.ledger, a.row, a.fp); },
    bills: function (a) { return getBills(a.cycle); },
    payday: function (a) { return getPayday(a.payday); },
    setBillFunded: function (a) { return setBillFunded(a.cycle, a.row, a.payday, a.funded, a.payer); },
    setBillNotes: function (a) { return setBillNotes(a.cycle, a.row, a.text); },
    carryBill: function (a) { return carryBill(a.cycle, a.row); },
    newCycle: function (a) { return newCycle(a.cycle); },
    addBill: function (a) { return addBill(a.bill); }
  };
  // A lookup, never ops[op]() on an arbitrary string against `this`: the map
  // is the whole list of what a request can reach.
  return Object.prototype.hasOwnProperty.call(ops, String(op)) ? ops[String(op)] : null;
}

/**
 * Which class of problem a plain-language message describes. The client needs
 * this to decide what to do with a queued write: park it for the user
 * (conflict), retry it later (server), or ask for sign-in (auth). The strings
 * are matched loosely on purpose — they are the messages the handlers already
 * raise, and this map is the one place that has to know them.
 */
function kindOf_(message) {
  var m = String(message || '');
  if (m.indexOf('access list') > -1 || m.indexOf('sign in') > -1) return 'auth';
  if (m.indexOf('changed') > -1 || m.indexOf('already') > -1 ||
      m.indexOf('could not be found') > -1 || m.indexOf('was voided') > -1 ||
      m.indexOf('added by hand') > -1) return 'conflict';
  if (m.indexOf('busy right now') > -1) return 'server';
  return 'validation';
}

function apiOk_(data) {
  return JSON.stringify({ ok: true, data: data === undefined ? null : data });
}

function apiErr_(message, kind) {
  return JSON.stringify({ ok: false, error: String(message), kind: kind || kindOf_(message) });
}

function apiJson_(text) {
  return ContentService.createTextOutput(text).setMimeType(ContentService.MimeType.JSON);
}

/**
 * The verified email inside a Google ID token, or '' when it does not check
 * out. Verification is Google's tokeninfo endpoint rather than local
 * signature checking: one HTTPS call, no key handling, and the result is
 * cached until the token expires so it costs about one call an hour per
 * device rather than one per tap.
 *
 * `aud` must be OUR client id. Without that check any valid Google token from
 * any app would pass — this is the difference between "a real Google user"
 * and "a user of this app".
 */
function verifyEmail_(token) {
  var raw = String(token || '');
  if (!raw) return '';

  var cache = CacheService.getScriptCache();
  var key = 'tok_' + Utilities.base64Encode(
    Utilities.computeDigest(Utilities.DigestAlgorithm.SHA_256, raw));
  var hit = cache.get(key);
  if (hit) return hit;

  var wanted = PropertiesService.getScriptProperties().getProperty('OAUTH_CLIENT_ID') || '';
  if (!wanted) return '';

  var res = UrlFetchApp.fetch(
    'https://oauth2.googleapis.com/tokeninfo?id_token=' + encodeURIComponent(raw),
    { muteHttpExceptions: true });
  if (res.getResponseCode() !== 200) return '';

  var info = JSON.parse(res.getContentText());
  if (info.aud !== wanted) return '';
  if (String(info.email_verified) !== 'true') return '';

  var email = String(info.email || '').toLowerCase();
  if (!email) return '';

  // Cache only until the token itself dies, and never longer than the
  // service's own ceiling.
  var left = Number(info.exp || 0) - Math.floor(Date.now() / 1000);
  if (left > 30) cache.put(key, email, Math.min(left - 30, 21600));
  return email;
}

/**
 * The one entry point for the PWA. Always answers with JSON, including for a
 * crash: the client parses `ok` and never an HTML error page.
 *
 * The body arrives as text/plain because Apps Script cannot answer a CORS
 * preflight, and a JSON content type would provoke one (spec §3.1).
 */
function doPost(e) {
  var body;
  try {
    body = JSON.parse((e && e.postData && e.postData.contents) || '{}');
  } catch (err) {
    return apiJson_(apiErr_('That request could not be read.', 'validation'));
  }

  var email = verifyEmail_(body.token);
  if (!email) return apiJson_(apiErr_('Sign in again to continue.', 'auth'));
  if (allowed_().indexOf(email) < 0) {
    return apiJson_(apiErr_('Your Google account is not on this app\'s access list.', 'auth'));
  }

  var handler = opHandler_(body.op);
  if (!handler) return apiJson_(apiErr_('That request is not something this app does.', 'validation'));

  // The handlers read the signed-in user from the session. Under this
  // deployment the session is the owner's, so the verified email from the
  // token is what identity must come from — API_EMAIL is how currentUser_
  // learns it for the length of this request.
  var props = PropertiesService.getScriptProperties();
  props.setProperty('API_EMAIL', email);
  try {
    return apiJson_(apiOk_(handler(body.args || {})));
  } catch (err) {
    var m = String((err && err.message) || err);
    return apiJson_(apiErr_(m, kindOf_(m)));
  } finally {
    props.deleteProperty('API_EMAIL');
  }
}

function apiSelfCheck_() {
  function eq(got, want, what) {
    if (got !== want) throw new Error(what + ': got ' + JSON.stringify(got) + ', want ' + JSON.stringify(want));
  }

  eq(typeof opHandler_('addEntry'), 'function', 'a known op resolves');
  eq(opHandler_('nonsense'), null, 'an unknown op does not');
  eq(opHandler_('toString'), null, 'nor does an inherited property');
  eq(opHandler_('constructor'), null, 'nor constructor');
  eq(opHandler_(''), null, 'nor a blank op');

  eq(JSON.parse(apiOk_({ a: 1 })).ok, true, 'a success is ok');
  eq(JSON.parse(apiOk_({ a: 1 })).data.a, 1, 'and carries its data');
  eq(JSON.parse(apiOk_(undefined)).data, null, 'a handler that returns nothing sends null');

  var err = JSON.parse(apiErr_('That entry changed. Reload and try again.'));
  eq(err.ok, false, 'a failure is not ok');
  eq(err.error, 'That entry changed. Reload and try again.', 'the message travels verbatim');
  eq(err.kind, 'conflict', 'and is classed as a conflict');

  eq(kindOf_('That entry changed. Reload and try again.'), 'conflict', 'a stale write');
  eq(kindOf_('That entry is already void.'), 'conflict', 'an already-applied write');
  eq(kindOf_('That bill could not be found. Reload and try again.'), 'conflict', 'a vanished row');
  eq(kindOf_('That entry was added by hand. Edit it in the sheet.'), 'conflict', 'an unstamped row');
  eq(kindOf_('The sheet is busy right now. Try again in a moment.'), 'server', 'a lock timeout is retryable');
  eq(kindOf_('Your Google account is not on this app\'s access list.'), 'auth', 'an access refusal');
  eq(kindOf_('Enter an amount greater than zero.'), 'validation', 'anything else is the user\'s input');

  console.log('api self-check passed');
}
```

```js
// Money and dates, formatted the way the Apps Script app formats them, so the
// two front ends do not look like two different apps during the parallel run.
const peso_ = new Intl.NumberFormat('en-PH', {
  minimumFractionDigits: 2,
  maximumFractionDigits: 2,
});

const MONTHS = ['jan', 'feb', 'mar', 'apr', 'may', 'jun',
                'jul', 'aug', 'sep', 'oct', 'nov', 'dec'];

/** ₱1,500.00 — a real minus sign for negatives, never a hyphen. */
export function peso(n) {
  const v = Number(n) || 0;
  return (v < 0 ? '−' : '') + '₱' + peso_.format(Math.abs(v));
}

/** +₱1,500.00 / −₱1,500.00 — the sign IS the direction (sibling spec §3). */
export function signed(n) {
  const v = Number(n) || 0;
  return (v < 0 ? '−' : '+') + '₱' + peso_.format(Math.abs(v));
}

/** 'sep 16' from 'YYYY-MM-DD', split by hand rather than parsed as a Date:
    new Date('2026-09-16') is UTC midnight, which is the day before in Manila. */
export function day(iso) {
  const m = /^(\d{4})-(\d{2})-(\d{2})$/.exec(String(iso || ''));
  if (!m) return '';
  const month = MONTHS[Number(m[2]) - 1];
  return month ? month + ' ' + Number(m[3]) : '';
}

/** Today as 'YYYY-MM-DD' in the phone's own calendar, for the date field. */
export function today(d = new Date()) {
  return d.getFullYear() + '-' +
    String(d.getMonth() + 1).padStart(2, '0') + '-' +
    String(d.getDate()).padStart(2, '0');
}
```

- [ ] **Step 3: Write `app/queue.js`**

Requirements, exactly:

- `enqueue(store, op, args)` stores `{id: crypto.randomUUID(), op, args, at: Date.now(), state: 'pending'}` and returns it.
- `drain(store, send)` walks `listQueue()` oldest first, skipping anything not
  `pending`. For each it awaits `send(item)` and then:
  - `{ok: true}` → `removeQueued(item.id)`, count a send;
  - `{ok: false, kind: 'conflict'}` → `putQueued({...item, state: 'parked', error})`, count a park, keep going;
  - `{ok: false, kind: 'auth'}` → stop, return `{needsAuth: true, stopped: true}`;
  - anything else (`server`, a thrown network error) → stop, leave the item pending.
- It returns `{sent, parked, stopped, needsAuth}` with numbers for the counts
  and booleans for the flags.
- `pendingFor(queue, account)` sums `args.entry.amount` over `pending`
  `addEntry` items for that account. This is the single piece of client-side
  money arithmetic the design allows (spec §7.3) — say so in a comment,
  including that it is never persisted and never sent anywhere.
- Comments explain the two rules that are not obvious: why a conflict parks
  rather than stops (one stale edit must not block a shop's worth of entries),
  and why anything else stops (a network that just failed will fail again, and
  order matters).
