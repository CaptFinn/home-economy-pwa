# PWA Stage 2 — Ledger Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the PWA to parity with the Apps Script app's ledger side — switch books, see recent entries and the full log, edit and void — with the wiring finally under test.

**Architecture:** Client-only, except one line in the sibling Apps Script repo (Task 6). Every op is already live in `Api.gs`. One page, three views switched in JS, no router. Edits and voids ride the existing offline queue; the server's fingerprint check refuses stale ones and the client parks them.

**Tech Stack:** Browser-native ES modules, IndexedDB, a hand-written service worker; `node` as a bare assertion runner. No bundler, no npm, no dependencies.

**Spec:** `docs/superpowers/specs/2026-09-19-pwa-stage-2-ledger-parity.md` — read it before any task. Parent design: `2026-09-16-pwa-client-design.md`.

**Repo:** `/home/captfinn/Documents/Claude/Claude_Code_Projects/home-economy-pwa-client` unless a task says otherwise. Task 6 also touches `/home/captfinn/Documents/Claude/Claude_Code_Projects/Home_Economy_PWA` (branch off `main`, commit there, never in the same commit).

## Global Constraints

- **Modern ES modules** on the client (`const`/`let`, arrows, `async`/`await`); **ES5** in the Apps Script repo. No bundler, no npm, no dependencies, either side.
- **Comprehension-first:** non-obvious choices get a comment saying *why*.
- **No money rule on the client.** The only client arithmetic remains summing queued amounts for a pending badge.
- **The wire contract is unsigned `amount` plus `direction`.** The server applies the sign, once. Re-introducing a pre-signed amount is the stage 1 Critical; Task 1 pins it.
- **Nothing may silently strand money.** Every path either retries itself or shows a state the person can act on. A status that can report a success it did not achieve is a defect.
- **All user text enters the DOM via `textContent`**, never string-built HTML.
- **Never write a raw NUL byte.** `check.sh`'s node blocks are single-quoted shell: inserted JS must contain no single-quote character.
- **No agent touches the sheet, the Apps Script project online, Google Cloud, or GitHub.** No `clasp`, no `gh`, no `git push`.
- **Verification:** `./check.sh` from the repo root must stay green (`fmt`, `db`, `queue`, `api`, `ui`, and from Task 1 also `wiring self-check passed`). In the sibling repo, its own `./check.sh` must print its six lines; the mid-run `TypeError: x.y is not a function` trace there is EXPECTED.
- **Bump `CACHE` in `sw.js`** in any commit that changes a file the service worker precaches, or an installed phone keeps the old code.

// drawn — it catches what actually broke in stage 1: a renamed field, a

// above all an entry that reaches the queue in the wrong shape.
import assert from 'node:assert/strict';

// ── a DOM small enough to read, large enough to wire ──────────────────
export function makeDom() {
  const byId = new Map();

  const make = (tag = 'div') => {
    const el = {
      tagName: String(tag).toUpperCase(),
      children: [],
      attributes: {},
      dataset: {},
      style: {},
      className: '',
      textContent: '',
      value: '',
      disabled: false,
      hidden: false,
      listeners: {},
      appendChild(child) { this.children.push(child); return child; },
      setAttribute(k, v) { this.attributes[k] = String(v); if (k === 'id') byId.set(String(v), this); },
      getAttribute(k) { return k in this.attributes ? this.attributes[k] : null; },
      addEventListener(type, fn) { (this.listeners[type] ||= []).push(fn); },
      removeEventListener() {},
      dispatch(type, event = {}) {
        for (const fn of this.listeners[type] || []) fn({ type, preventDefault() {}, target: this, ...event });
      },
      querySelector() { return null; },
      querySelectorAll() { return []; },
      focus() {},
      scrollIntoView() {},
      remove() {},
    };
    Object.defineProperty(el, 'id', {
      get() { return this.attributes.id || ''; },
      set(v) { this.setAttribute('id', v); },
    });
    return el;
  };

  const document = {
    createElement: (tag) => make(tag),
    getElementById: (id) => byId.get(id) || null,
    querySelector: () => null,
    addEventListener() {},
    body: make('body'),
  };

  // The fixed elements index.html ships with.
  for (const id of ['screen', 'conn', 'whoami', 'foot']) {
    const el = make('div');
    el.id = id;
    byId.set(id, el);
  }
  return { document, make, byId };
}

/** Every bit of text in a subtree, flattened — enough to assert what a
    render produced without pretending to be a browser. */
export function textOf(el) {
  if (!el) return '';
  const own = el.textContent || '';
  return [own, ...el.children.map(textOf)].filter(Boolean).join(' ');
}

/** Depth-first search for the first element matching a predicate. */
export function find(el, fn) {
  if (!el) return null;
  if (fn(el)) return el;
  for (const child of el.children) {
    const hit = find(child, fn);
    if (hit) return hit;
  }
  return null;
}

In `src/Api.gs`, the inner `try` wraps `apiJson_(apiOk_(handler(...)))`, so a throw from `JSON.stringify` or `ContentService` — neither sanitised by `safe_` — would be relayed verbatim. Compute the handler's result inside the `try` and serialise outside it:

      API_EMAIL_ = '';
    }
    return apiJson_(apiOk_(out));

### Task 7: Runbook

**Files:** `docs/RUNBOOK.md`

- [ ] **Step 1: Add a stage 2 section**

No sheet change, no new property, no new deployment — say so first, so nobody goes looking. Then the checks that only a person can do:

1. Switch ledgers; confirm the accounts change and the choice survives a reload.
2. Venice switches on her phone; confirm your ledger does **not** move — the choice is per person.
3. Edit an entry's amount; confirm the sheet's `Logged by` and `Logged at` are unchanged and `Status` reads `edited …`.
